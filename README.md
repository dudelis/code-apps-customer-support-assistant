# Customer Support Assistant

Customer Support Assistant is a Power Apps Code App built as a step-by-step video series. The goal is to show how to build a real support experience inside the Power Platform without hiding the implementation behind heavy abstractions or generated screens.

This repository is doing two things at once:

- building a modern support workspace for agents and managers;
- documenting a practical learning path for React developers working with Power Apps, Dataverse, connectors, flows, and Copilot Studio.

## What We Are Building

The app gives support teams a focused interface for handling customer work:

- review tickets, customers, tasks, and activity in one place;
- give agents a fast dashboard instead of a crowded model-driven form experience;
- enrich the UI with Microsoft 365 data such as user profile details and calendar events;
- prepare the app for Dataverse-backed ticket data, Power Automate workflows, and Copilot Studio assistance.

Today, the repository already contains a polished UI prototype and live Microsoft 365 connector integration. The next stages move the app from mocked business data into a real Power Platform implementation.

## Why This Project Exists

Support teams often need something more tailored than a standard business app screen, but they still want to stay inside the Power Platform ecosystem. A Code App is the right middle ground:

- custom React UI where the experience matters;
- Power Apps hosting and identity so there is no separate auth stack to build;
- Dataverse, Power Automate, and connectors for the business system side;
- Copilot Studio as a natural extension for AI-assisted support work.

The repo is also intentionally instructional. Each part of the series adds one capability at a time so the code stays readable and easy to follow.

## How The App Is Structured

Inside `app/src/`, the code follows a simple flow:

```text
components -> hooks -> services -> Power Platform or mock data
```

- `components/` keeps UI concerns local and readable
- `hooks/` own loading, error, and view state
- `services/` contain integration logic
- `generated/` holds connector code generated by the PAC CLI
- `data/` contains mock data until Dataverse replaces it

This structure is deliberate: it keeps the teaching story clear and makes each new video part easy to layer on top of the previous one.

## Project Principles

- keep the code simple enough for viewers to follow;
- prefer explicit patterns over clever abstractions;
- build real Power Platform integrations incrementally;
- keep the UI fast, focused, and useful for support agents.

## Notes For Contributors

- root-level documentation explains the project and series;
- implementation work happens in `app/`;

- the `memory-bank/` folder tracks current context, progress, and architectural decisions.
